두 문제를 이름 치환으로 확정 수정하지 않고 출제에서 제외한다.

## 기존 방식의 한계

`small.en`은 문맥상 그럴듯한 철자를 높은 점수로 출력할 수 있다. 재전사에서도
`Gotti Eisenkot`, `Piazz Isabella Gomez-Admiento`가 나왔다. 해당 구간의
`avg_logprob`는 약 -0.18, -0.23이었다. 기존 -1 기준뿐 아니라 새 -0.5 기준도
통과한다. 문장 점수를 정답 확률로 해석하거나 인명 철자 검증에 단독 사용하면 안 된다.
온도와 단어 시각 설정을 변경하면 이전 결과와 철자가 조금 달라질 수 있다.

동일한 음원의 `medium.en` 결과는 두 이름을 공식 철자대로 인식했다. 그러나 기자
이름 앞은 여전히 `Pierre's`로 출력했다. 이름이 개선됐다는 사실만으로 주변 문장까지
정답이라고 확정할 수 없으므로 두 문제는 계속 제외한다.

기존 구현은 낮은 신뢰도 구간 일부를 건너뛴 뒤 남은 구간을 연결할 여지가 있었고,
한 구간에 여러 문장이 있으면 선택한 문장보다 넓은 재생 범위를 저장했다.
새 구현은 단어 시각으로 문장과 재생 범위를 함께 만들며, 누락/불량 구간을 거친
문장은 다음 문장 경계까지 버린다.

| --- | --- | --- |

| 고유명사 위험 문장 제외 | 두 오류 문장을 철자 확정 없이 제거. 정상적인 이름/요일/기관명도 제외될 수 있음 | 텍스트 검사 비용은 미미. 문제 수가 줄어듦 |
| 전체 방송을 medium.en으로 전사 | 더 큰 모델이지만 고유명사와 사실 정확성은 보장하지 못함 | 매번 전체 방송 처리 비용과 약 1.53 GB 모델 다운로드 필요 |
| small.en + 후보 구간 medium.en 대조 (채택) | 두 모델의 단어·숫자 불일치를 제외. 동일한 오류에는 취약하므로 이름 제외도 병행 | 전체 방송 한 번 + 최대 12개, 각 18초 이하 후보 구간 처리. 모델 캐시 재사용 |
| 사람의 청취 및 공식 대본 대조 | 이름·문맥을 판단하는 최종 검증 수단 | 매일 사람의 검토 시간이 필요. 이번 자동 생성에는 포함하지 않음 |

모델 기능과 성능 조건은 [faster-whisper 공식 문서](https://github.com/SYSTRAN/faster-whisper),
모델 규모는 [Whisper 공식 문서](https://github.com/openai/whisper)를 참고했다.
다른 장비의 벤치마크 수치를 GitHub Actions 실행 시간으로 간주하지 않는다.

## 적용 기준

- 생성기 버전 6, CPU int8, 4스레드, beam 5, temperature 0, 영어 고정.
- `avg_logprob >= -0.5`, `no_speech_prob <= 0.3`, `compression_ratio <= 2.4`.
  점수가 없거나 유한하지 않아도 제외한다.
- 모든 단어 신뢰도 0.65 이상, 빈칸 정답의 1차 단어 신뢰도 0.85 이상.
- 9~24단어, 2~18초, 문장 끝 구두점과 대문자 시작 확인. 25초 이전은 제외.
- 문장 첫 단어를 제외한 대문자 단어(I 제외), 기자 소개 `reports/reporting`은 제외.
  이는 보수적인 휴리스틱이며 문두 이름이나 소문자로 잘못 인식한 이름까지 탐지하지는 못한다.
- 최대 12개 후보를 `medium.en`으로 이름 힌트 없이 재전사한다. 두 번째 전사도
  품질 검사를 통과하고 단어·숫자가 일치해야 채택한다. 대소문자와 일반 구두점 차이만 허용한다.
  앞뒤 최대 2초의 문맥을 포함해 잘린 첫 단어의 인식 문제를 줄이고, 단어 시각으로
  대상 문장만 비교한다. 문맥 부분의 단어를 정답이나 문제 문장에 추가하지 않는다.
- 14초 이상 간격을 둔 1~5개 문제를 제공한다. 문장이 부족하다고 기준을 완화하지 않는다.
  한 개도 통과하지 못하면 실패하고 이전 파일을 보존한다. 저장은 임시 파일 완성 후 교체한다.
- `verified: false`, 기존 한국어 미검증 안내, 문제별 안내를 유지한다.
  별도 `transcription` 메타데이터는 모델 대조와 사람 검증을 구분한다.

## 재현과 검증

`python -m unittest discover -s tests -v`로 오류 인명, 낮거나 누락된 점수,
문장 연결, 단어별 재생 범위, 숫자 불일치, 모델 불일치 시 비수정,
생성 실패 시 기존 파일 보존을 검사한다. 일일 작업도 전사 전에 테스트를 실행한다.

`python scripts/audit_audio.py`와 `python scripts/check_audit_candidates.py`는
실제 음원 비교 결과를 로컬 `.audit/`에 기록한다. `--resume`으로 같은 회차 비교를
재개할 수 있다. 음원·전체 전사본·모델 파일은 커밋하지 않는다.
표본 한 회차와 두 이름만으로 전체 단어 오류율이나 이름 정확도를 산출하지 않는다.

medium.en 전사 시간은 이 표본에서 small.en의 약 4.0배였다. 준비 시간은 캐시와
네트워크에 좌우된다. medium.en의 최초 Xet 다운로드는 중단 후 일반 HTTP 방식으로
재시도했으며 표에는 성공한 재시도의 준비 시간만 기록했다. 전체 조사 경과 시간이나
GitHub Actions의 예상 소요 시간으로 사용하면 안 된다.

채택한 후보 재검사에서는 후보 2개 중 1개가 통과했다. 캐시가 있는 medium.en의
준비 시간은 4.69초, 두 구간의 전사·검사 시간은 21.14초였다. 1차 전사 시간과
합치면 97.07초(모델 준비 제외)로, 전체 방송을 두 모델로 처리한 381.44초보다 짧다.
15개 회귀 테스트와 실제 원본 음원 후보 검사를 수행했다. 대상 문제 파일은 기준을
통과한 문장만 남도록 재생성하며, 알려진 두 인명 문장은 포함하지 않는다.

처음에는 앞뒤 0.15초만 덧붙인 짧은 재전사를 시도했지만 두 후보의 첫 단어 점수가
0.52, 0.48로 낮아 모두 탈락했다. 신뢰도 기준을 낮추지 않고 문맥 길이를 보완했다.
두 번째 후보에는 여전히 낮은 신뢰도 단어가 남아 최종 출제에서 제외했다.
