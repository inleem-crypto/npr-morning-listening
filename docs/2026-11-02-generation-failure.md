## 재현한 경계 처리 결함과 수정

기존 검사는 small.en의 시작~종료에 ±0.1초를 더한 범위에 medium.en 단어의
중간 시각이 들어와야 비교 대상으로 삼았다. 같은 문장을 전사해도 단어 시각이
0.6초 이동하면 첫 단어나 끝 단어가 잘려 문자열이 달라질 수 있다.
회귀 테스트로 같은 문장·같은 점수에서 이 오탈락을 재현했다.
이는 실제 코드 결함의 증거이며 당시 4개 탈락의 원인이었다는 증거는 아니다.

v7은 문맥 포함 전사에서 정규화된 전체 문장·숫자와 정확히 일치하는 연속 구간을
찾는다. 삽입/삭제/치환이나 유사도 기준은 사용하지 않는다. 양쪽 경계는 각각
1차 시각과 0.75초 이내여야 하고 문장 경계, 단어 경계, 유일한 일치,
유효한 순서의 단어 시각과 연속된 증거를 요구한다. 0.75초는 제한된 경계 허용값이며
정확도 확률이나 모든 회차에 대한 측정값이 아니다. 더 큰 이동은 계속 제외한다.

기존 점수 기준, 이름 제외, 정답 단어의 1차 강한 증거, 모델 두 개의 독립 전사,
14초 출제 간격, 1~5개 출제, `verified: false`는 유지한다. 0.75배속,
반복 청취, 빈칸 채점 코드는 변경하지 않는다.

## 실패 보존 및 운영 진단

- lesson.json은 통과 문장이 있을 때만 임시 파일 완성 후 교체한다.
- 성공/실패와 무관하게 generation-status.json을 별도로 저장하고 커밋한다.
  실패 시 작업 자체의 실패 표시는 유지한다. 실패를 성공으로 숨기지 않는다.
- generation-report.json에는 회차, MP3 SHA-256, 1차 후보, 2차 문맥 전사,
  기존 시간 창 전사, 단어별 시각·신뢰도·구간 점수와 사유를 저장한다.
  Actions 아티팩트로 30일 보존하며 전체 음원이나 모델 파일은 올리지 않는다.
- 사유: text_mismatch(전체 문장 불일치), boundary_mismatch(문장은 있지만
  시간/문장 경계 불충족), low_confidence, name_risk, ambiguous_alignment,
  accepted, accepted_boundary_recovery, spacing.
- 기존 문장을 숨기던 생성 시각 18시간 제한을 없앴다. 대신 문제 방송 시각(KST),
  최신 목록보다 오래된 방송 여부, 방송 등록 후 18시간 경과, 최근 갱신 실패를
  명시한다. 파일이 같아도 상태 안내는 주기적으로 다시 계산한다.
